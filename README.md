# Telegram Photo Counter Bot

Тестовый бот для группового Telegram-чата.

## Что умеет

- Пользователь отправляет фотографию.
- Бот отправляет эту же фотографию от своего имени с подписью `№127 · Иван Петров`.
- Исходное пользовательское сообщение удаляется.
- Ведётся общий и личный счётчик в JSON.
- `/top`, `/me`, `/total` показывают статистику.
- Администратор может удалить фото командой `/deletephoto N`.
- После удаления все следующие номера сдвигаются на 1, а подписи сообщений обновляются.
- Администратор может задавать сообщения на порогах: 50, 100, 250 фото и т.д.
- Сами изображения на сервере не хранятся: используется Telegram `file_id`.

## Команды

Пользовательские:

- `/me` — мой результат.
- `/top` — рейтинг участников.
- `/total` — общее количество действующих фото.
- `/help` — инструкция.

Администраторские:

- `/deletephoto 146` — удалить фото №146 и перенумеровать все следующие.
- `/milestones` — показать заданные пороги.
- `/addmilestone 100 Соточка! 🎉` — добавить/заменить сообщение.
- `/editmilestone 100 Новый текст` — изменить существующее сообщение.
- `/delmilestone 100` — удалить порог.

Админом считается либо администратор рабочей группы, либо Telegram ID из `ADMIN_IDS`.

## Важные права бота в группе

Добавьте бота администратором. Ему необходимо как минимум право удалять сообщения. Бот также должен иметь возможность отправлять сообщения и фотографии.

У обычных участников можно запретить текстовые сообщения, оставив разрешение на фотографии. Тогда рабочий чат будет использоваться только для фото, а подписи будет публиковать бот.

## BotFather

Для группового бота рекомендуется отключить Privacy Mode через `/setprivacy` -> Disable, чтобы бот гарантированно получал обычные сообщения с фотографиями в группе.

## Запуск локально

1. Создайте `.env` из `.env.example`.
2. Укажите `BOT_TOKEN`.
3. Запустите:

```bash
docker build -t photo-counter-bot .
docker run --rm --env-file .env -v "$(pwd)/data:/app/data" photo-counter-bot
```

## Bothost

Проект запускается long polling и не требует публичного HTTP-порта.

Переменные окружения:

```text
BOT_TOKEN=...
ADMIN_IDS=123456789,987654321
DATA_FILE=/app/data/state.json
```

### Важно про JSON

`state.json` является всей базой бота. При пересоздании контейнера локальная файловая система хостинга может быть очищена. Поэтому каталог `/app/data` должен находиться на постоянном диске/volume, если Bothost позволяет его подключить. Перед обновлением приложения также полезно делать резервную копию `state.json`.

Запись JSON выполняется атомарно: сначала создаётся временный файл, затем он заменяет основной.

## Поведение удаления

Было:

```text
№145 · Анна
№146 · Иван
№147 · Ольга
№148 · Сергей
```

После `/deletephoto 146`:

```text
№145 · Анна
№146 · Ольга
№147 · Сергей
```

Личный счёт Ивана уменьшается на 1. Следующее новое фото получит №148.

Уже сработавшие milestone-сообщения повторно не отправляются после удаления и повторного достижения того же числа.

## Ограничение Telegram

Telegram Bot API позволяет удалять сообщения только в пределах установленных Telegram ограничений (для обычных сообщений — в частности, действует ограничение по возрасту сообщения). Поэтому `/deletephoto N` может не удалить очень старое сообщение. Перенумерация запускается только если удаление сообщения в Telegram прошло успешно.
